# 什么代价——质量与成本的联合裁决

> 评测第 1 篇立了四问：能不能做对、坏了会不会察觉、是不是它的功劳、什么代价。前三问各有章节认领，第四问一直只有一句话：成本是一等约束。这一篇把这句话展开——不是讲怎么省钱，是讲**成本怎么进入 go/no-go 决策，以及成本账怎么记才不污染归因**。

## 一、开场：十八比十八，为什么仍然被否决

我持续在看的一个开源 agent 内核项目（单人维护；为保持小册独立，下面称它 M 项目，不点项目名，出处登记在写作简报里），它的评测台账里有一个反直觉的裁决。

一次配对实验：对照组和实验组各跑 18 个 rollout，**两组都 18/18 全成功**。质量上打平，实验组还多出一套机制。按「通过率说话」的习惯，这个实验该判实验组赢，至少是可以推广。裁决却是**拒绝**——因为实验组每个 rollout 多花了 0.0648 美元，而实验合同里预注册的成本门槛是 0.02 美元（见该项目的评测规范文档，2026-10 观察）。

<!-- 配图 eval09-quality-cost-frontier.svg：质量-成本散点 + Pareto 前沿，标注「18/18 但被否决」的点 -->

我第一次读到这个案例时停了一下。它逼出一个我自己 harness 里一直回避的问题：**只按质量裁决，等于给「花钱买通过率」开了后门。**

## 二、通过率是可以花钱买的

这不是比喻。至少有四条明码标价的通道：

1. **换更强的模型**。同一个 harness、同一批题，模型升一档，分数涨一截，单价也涨一截。
2. **重试**。偶发失败重跑，pass@k 随 k 爬向 1.0——评测第 6 篇讲过，这是「重跑治理」视角的遮羞布。
3. **堆上下文**。更多规则文件、更多历史、更多 few-shot，弱模型也能被上下文抬着走。
4. **加密自检**。改完再让模型自查一遍、跑一轮 judge 复核，失败率会降，token 翻倍。

这四条通道有个共同特征：**在只报通过率的报告里，它们全部隐身**。一个 80% 通过率但平均花 2 美元的臂，和一个 78% 通过率花 0.2 美元的臂，在「pass rate 排行榜」上前者赢；在真实产品里，后者可能是唯一能上线的那个。

我自己的数字也能重算一遍。截断检出矩阵（评测第 4 篇）每格跑三次，108 格里每一次复测都是真金白银的会话；skill-up 的 `--iteration N` 采样模式（《给 skill 建门禁》一篇）为了把置信区间压窄要多跑好几轮——这些钱当时花得都对，但**「花得对」的判断从来没被写进任何裁决规则**，全靠手感。没有成本轴的 pass rate 是单目视觉：看得见高低，看不见远近。

## 三、裁决的三个量：cost per success、边际成本、前沿拐点

把成本放进裁决，需要三个量，而不是一个总价。

**每个成功结果的成本（cost per successful outcome）。** 分母是成功数，不是运行数。一个臂跑 100 次成 50 次花 100 美元（2.0 美元/成功），另一个跑 100 次成 40 次花 20 美元（0.5 美元/成功）——后者用前者四分之一的「买到一个成功」的价格，只低了 10 个百分点。预算受限的真实运营里，这意味着同样的钱能覆盖四倍的用户量。

**边际成本：下一个百分点多少钱。** 从 60% 买到 70% 可能每个百分点 5 美元，从 85% 买到 86% 可能是 50 美元。决策不是「要不要更强的方案」，是「我现在在曲线的哪一段」。

**质量-成本 Pareto 前沿。** 把每个方案画成散点，连线找出「质量相同我最便宜、成本相同我最好」的前沿。前沿上的方案才有资格被讨论，前沿里面的方案不需要理由就可以淘汰——M 项目那个 18/18 的臂之所以被否，不是因为它差，是因为它落在了前沿的**内**侧：同样的质量，对照组更便宜。

一个公开的参照系是 typed-decision 模型的第三方榜单 JevBench：它把 Cost 和 Intelligence、Calibration、Speed 做成**等权几何平均**的四个轴，成本按「每 1000 次决策多少美元」计价（不是每 1000 token），每贵 10 倍扣 30 分。计价单位选「每次决策」而不是「每千 token」是有深意的：token 是模型厂商的计费单位，决策才是用户的消费单位——用户要的是「我这个 agent 每做一次判断付多少钱」，不是「它吐了多少字」。

## 四、成本首先是实验卫生问题

读到这里容易以为成本是经济话题。不是。在评测里，**成本首先是归因问题**：两臂的计费路径不一致时，效果差 Δ 和成本差同时无法归因。

### 零静默重试

最隐蔽的成本失真是静默重试。请求超时了，SDK 默认帮你重试两次；provider 返回 503，代理层悄悄换个节点再发一次。账面上你看到的是「这次成功了、花了这些 token」，实际上你买到的是「三次尝试里有一次成功」——而对照组可能因为没有同样的重试配置，只试了一次。

M 项目的付费 runner 直接把这个口子焊死：代理层把自动重试次数钉死为零，每次请求单独授权，撞上 503 也写一条「已授权但失败」回执，永不自动重试。它的评测规范文档里把这条写成铁律，理由有两层：重试既**通胀成本**（一个样本实际花了三份钱却记一份），又**抹平差异**（鲁棒性本来就是两个臂的差异之一，重试把这个差异偷偷消掉了）。

我在 dsh harness 里踩过这个问题的镜像面：失败重跑会被上一次尝试残留的文件副作用污染（《从 trace 到 eval》一篇里写过，连 git history 都能被 agent 翻出来作弊式获利）。重试污染的从来不只是状态，还有账本。

### 缓存是长上下文实验最大的隐性变量

第二个失真源是 prompt cache。长上下文会话里，前缀的几万 token 走缓存命中和走全价，成本可以差一个数量级。这制造了一种实验者很难察觉的耦合：**你对干预的任何改动，都可能顺手打穿缓存。**

M 项目在设计停滞熔断（stall gate）时否掉过一个方案——「检测到空转时，限制下一轮的 tool_choice」。否掉的理由里有一条纯经济学的：改 tool_choice 会让 provider 的消息缓存失效，在 400K–850K 上下文的场景里，那是全场最贵的一次 cache miss，而这个方案只是为了发一个模型大概率无视的信号（76% 的进度提醒本来就被无视，评测第 11 篇汇总了这类文本型干预的失效证据）。一次干预的成本不只是它自己的 token，还有它顺手作废的那截缓存。

<!-- 配图 eval09-cache-miss.svg：长请求条上缓存命中段 vs tool_choice 改动后全段 cache creation 全价重算 -->

记账时 usage 必须分项：input、output、cache read、cache creation。我自己的 trace 提取层当时定过一个口径——门禁的总量字段排除缓存命中、缓存读写单列观察，那是为漂移检测服务的；算成本账时要反过来，**缓存读按折扣价如实计入**，两个口径不能混用，只报一个 total token 等于瞒账。

## 五、对照组的计费路径必须逐字节对齐

这一节是评测第 10 篇配对手册的预演，但成本侧值得单独点破：**两臂除 treatment 外，计费路径必须一致**。

- 同一个模型版本、同样的温度与采样配置；
- 同样的重试策略（最稳妥是两臂都零重试）；
- 同样的默认功能开关——这是最容易漏的。M 项目的记忆 runner 出过一个真实事故：对照组忘了关默认开启的内置判官，结果对照组「悄悄」用上了和实验组同源的能力，A/B 直接报废；
- 同样的缓存条件——两臂的前缀要一样长、一样的内容，否则 cache miss 率的差异会被误记成 treatment 的成本效应。

他们构建系统里的做法值得抄：每一步测试默认把判官服务的接入地址导出为关闭态，eval harness 给每个 arm 先设关闭，需要判官的臂再显式换成自己的端点。**默认值永远站在「污染」那一边，对照组的「无」必须是强制出来的**——这句话评测第 6 篇立过，成本记账是它的又一个适用面。

## 六、美元门槛要在花钱之前写死

最后一块拼图：预算和停止规则必须**预注册**——在看到任何数据之前写进实验合同。至少五个字段：

1. 累计授权金额（花完即停，不许边跑边追加）；
2. 单样本成本上限（异常昂贵的失控样本怎么处理）；
3. 超支样本的归属（记 invalid 还是计入分母——二选一，先定）；
4. 成本门槛（每成功结果多少钱以内才算「不更贵」）；
5. 到达预算后的动作（停止并按已有数据判，还是挂 Blocked 等下次授权）。

M 项目的记忆排序试点合同里，累计授权就是 15 美元、shard 顺序执行；前面那个 0.02 美元门槛也是在实验开始前写死的，所以 18/18 打平时裁决毫无尴尬——规则先于结果，执行规则不需要勇气。

这套纪律和评测第 7 篇讲的预注册停止规则是同一回事的两面：统计上的停止规则防止「偷看数据决定要不要继续跑」，美元门槛防止「效果不显著就加钱硬买」。**事后追加的预算和事后追加的样本一样，都会把探索性分析伪装成确认性结论。**

## 七、四问的闭环

评测第 1 篇的四问到此全部有主：能不能做对（评测第 2–5 篇）、坏了会不会察觉（评测第 3–5 篇）、是不是它的功劳（评测第 6、10 篇）、什么代价（本篇）。

还有一条刻意留下的缝：本篇讲的是**裁决与记账**——钱花了多少、买到了什么、该不该继续花。但「花掉的上下文有多少真正有效」是另一个问题：800K 上下文里模型实际在认真读的可能只有 20K，有效窗口随长度衰减。这条线（context-tps 有效窗口横评）是已预留编号 eval08 的选题，本篇不展开——成本是价格问题，有效窗口是质量问题，两个账本分开记，将来与 eval08 合账。
