## 必配 7 张（每章一张）

### 1. eval01-four-questions-map.svg（本卷目录图，作者已拍板）

- **支撑论点**：agent eval 收拢为四个问题，后续每章认领一问。
- **画什么**：左侧竖列六层被测对象，自下而上：模型 / 流式协议 / 宿主 harness / 内容与扩展（skill·插件）/ 生态 / 仓库与上游。右侧横排四问：能不能做对 / 坏了会不会察觉 / 是不是它的功劳 / 什么代价。三条色带横穿六层连接四问，标三个姿势名：能力评测（连"做对"）、故障注入（连"察觉"）、对照实验（连"功劳"）；"代价"一问标虚线（本卷暂不展开）。每章编号 eval01–07 作为小标签贴在对应格子上。
- **图型**：分层地图 / 矩阵。

### 2. eval02-failure-to-testcase.svg

- **支撑论点**：评估器该为已发现的错误而建，不为想象中的错误而建；红绿对照是用例的出生证明。
- **画什么**：一条横向流水线：真实失败（线上/实验中） → 亲手标注（开放编码） → 失败分类表 → 指名道姓的红测试（标 FAIL） → 修复 → 转绿（标 PASS） → 进回归套件常驻。下方画一条废弃支路（虚线）：想象中的错误 → 直接造用例 → 产出噪声，打 ✗。红测试节点要强调"名字"（测试名=踩坑边界的登记簿）。
- **图型**：横向流程图 + 废弃支路。

### 3. eval03-green-light-lies.svg

- **支撑论点**：两种谎言踩进同一个危险格子——两个世界产出同一个绿灯，观测对差异就是盲的。
- **画什么**：2×2 矩阵，横轴=真实状态（好/坏），纵轴=检查结果（绿/红）。三个格正常着色，唯一高亮格是「状态坏 × 检查绿」（危险格）。两个箭头从左侧进入该格：箭头 A 标「检查问错了问题」（例：问"文件在不在"而非"目录能不能信"——平时全对，只在分叉日暴露）；箭头 B 标「被测的事根本没发生」（例：绕行、静默降级——检查全对但世界是坏的）。图底放定律句：「当两个不同的世界产出同一个绿灯，你的观测对它们的差异就是盲的」。
- **图型**：2×2 矩阵概念图。

### 4. eval04-108-grid.svg（本篇主图）

- **支撑论点**：检出不难，告知才是缺口；检出与否取决于伤是否挡路，而非伤有多重。
- **画什么**：一张大矩阵（约 6 列 × 多行）：列=宿主/引擎脚手架，行=伤型（截主文件/删附件/截附件/清 frontmatter/模板截半/85% 剂量档），格子按行为分级 L0（无察觉）–L3（拒绝执行）着色，L0 用压倒性的灰白面积呈现（约六成格子是 L0）。旁注两个对比数字：挡路的伤 8/8 检出 vs 不挡路的伤 2/8。图底小字：宿主矩阵含脚手架×模型双变量，不做归因拆分。
- **图型**：大矩阵 / 热力图（手绘感，不要精确比例，传达"大面积无声"即可）。

### 5. eval05-three-factors.svg（全卷核心模型图）

- **支撑论点**：检出率 = 读到 × 愿报 × 挡路，三因子缺一即未检出，且可归因到断掉的那一级。
- **画什么**：三道串联的闸门（或漏斗三段），水流从左向右：①**读到**——伤在 agent 要走的路上吗（失效形态注：T3 型，伤件从未被打开）；②**愿报**——察觉了肯说吗（失效形态注：「察觉了但没报」是最危险的未检出形态）；③**挡路**——说了会停下来吗（失效形态注：检出 ≠ 止损，报了照样跑完）。出口两岔：检出 / 未检出；未检出岔口画一条反向虚线箭头沿三道闸门折返，标「未检出 → 反推断在哪道闸」。图顶公式：检出率 = 读到 × 愿报 × 挡路。
- **图型**：串联闸门 / 漏斗。

### 6. eval06-two-arms.svg

- **支撑论点**：归因靠对照，不靠证据强度；对照组选错比没有对照组更危险。
- **画什么**：上半部正面示范：同一组用例分叉进两臂——with 臂（带插件/skill）与 without 臂（裸基线），两臂分数相减得 Δ = 真贡献，Δ 进报告首页。下半部反例区（打 ⚠）：对照组被污染的三种形态——拿老 profile 当对照 / 对照组靠默认值"自动出现" / 无裸基线直接报分——汇入同一句结论：「没有裸基线时，『全绿』和『没测到』长得一模一样」。
- **图型**：分支对照图（上正反例）。

### 7. eval07-meta-loop.svg

- **支撑论点**：裁判本身也要被校准；误报的价值不在改正，在长出机制。
- **画什么**：一个闭环（四节点环）：观测错误 / 误报 → 产出假结论 → 公开翻案（v1 错误归因原样保留，标注"更正成本=一次尴尬，收益=可信的轨迹"） → 长出新机制（环上挂四个小标签：排除计数 / 判活器自测 / 绝对路径纪律 / flaky 与 error 分账） → 回到起点，下一轮测量更可信。环心一句：**裁判的 bug 比被测对象的更隐蔽**。
- **图型**：循环图（中心句 + 环上机制标签）。

## 可选 6 张（作者定夺，可与出图 agent 议后砍）

### 8. eval02-trigger-confusion.svg
触发层双向口径：2×2 混淆矩阵（TP/FP/FN/TN），旁边挂一个"影子信号"侧袋（agent 绕过 Skill 工具直接 Read 文件—— substantive 但不进矩阵），标注「影子信号不作 recall 减免」。

### 9. eval03-bypass-channels.svg
六条绕行通道：一条主流程管道（请求 → 插件挂载 → 工具执行 → 产出 → 判定），六个旁路出口各标一名（静默降级 / mock 只走 happy path / 直写 grader 要看的结果文件 / skip 静默生效 / 兜底吞主路 / grader 只看终态），每条旁路都绕到同一个"绿灯"终点。

### 10. eval04-injection-pipeline.svg
方法学红线长在管线里：变异脚本只动副本 → 哈希匿名暂存（宿主可见路径不得编码伤型） → 零上下文 headless 宿主 → 机械证人与 agent 评卷分层记录 → C0 阴性对照全程压阵。

### 11. eval05-dose-position.svg
剂量-位置效应小图：两根对比柱（挡路的伤 8/8 vs 不挡路的伤 2/8）+ 剂量梯度注（主文件 100% 删除 vs 截到 85%，检出差异）。

### 12. eval06-passk.svg
两个数讲相反的故事：同一用例单次成功率 0.75，横轴 k=1…10，两条曲线——pass@k 爬向 1.0（"重跑治理"视角看着完美）vs pass^k 跌向 0.056（"可靠性"视角几乎必挂）。

### 13. eval07-book-closing.svg
全书收口图：三环递进——界面（把渲染变成可断言的）→ 基建（让承诺可信）→ 评测（把裁判也变成可断言的）；起点标全书开篇之问「没报错，就代表输出没问题吗？」，终点标「检查也会说谎，所以裁判也要被校准」。
