## 必配 7 张（每章一张）

### 1. eval01-four-questions-map.svg（本卷目录图，作者已拍板）

- **支撑论点**：agent eval 收拢为四个问题，后续每章认领一问。
- **画什么**：左侧竖列六层被测对象，自下而上：模型 / 流式协议 / 宿主 harness / 内容与扩展（skill·插件）/ 生态 / 仓库与上游。右侧横排四问：能不能做对 / 坏了会不会察觉 / 是不是它的功劳 / 什么代价。三条色带横穿六层连接四问，标三个姿势名：能力评测（连"做对"）、故障注入（连"察觉"）、对照实验（连"功劳"）；"代价"一问标虚线（本卷暂不展开）。每章编号 eval01–07 作为小标签贴在对应格子上。
- **图型**：分层地图 / 矩阵。

### 2. eval02-failure-to-testcase.svg

- **支撑论点**：评估器该为已发现的错误而建，不为想象中的错误而建；红绿对照是用例的出生证明。
- **画什么**：一条横向流水线：真实失败（线上/实验中） → 亲手标注（开放编码） → 失败分类表 → 指名道姓的红测试（标 FAIL） → 修复 → 转绿（标 PASS） → 进回归套件常驻。下方画一条废弃支路（虚线）：想象中的错误 → 直接造用例 → 产出噪声，打 ✗。红测试节点要强调"名字"（测试名=踩坑边界的登记簿）。
- **图型**：横向流程图 + 废弃支路。

### 3. eval03-green-light-lies.svg

- **支撑论点**：两种谎言踩进同一个危险格子——两个世界产出同一个绿灯，观测对差异就是盲的。
- **画什么**：2×2 矩阵，横轴=真实状态（好/坏），纵轴=检查结果（绿/红）。三个格正常着色，唯一高亮格是「状态坏 × 检查绿」（危险格）。两个箭头从左侧进入该格：箭头 A 标「检查问错了问题」（例：问"文件在不在"而非"目录能不能信"——平时全对，只在分叉日暴露）；箭头 B 标「被测的事根本没发生」（例：绕行、静默降级——检查全对但世界是坏的）。图底放定律句：「当两个不同的世界产出同一个绿灯，你的观测对它们的差异就是盲的」。
- **图型**：2×2 矩阵概念图。

### 4. eval04-108-grid.svg（本篇主图）

- **支撑论点**：检出不难，告知才是缺口；检出与否取决于伤是否挡路，而非伤有多重。
- **画什么**：一张大矩阵（约 6 列 × 多行）：列=宿主/引擎脚手架，行=伤型（截主文件/删附件/截附件/清 frontmatter/模板截半/85% 剂量档），格子按行为分级 L0（无察觉）–L3（拒绝执行）着色，L0 用压倒性的灰白面积呈现（约六成格子是 L0）。旁注两个对比数字：挡路的伤 8/8 检出 vs 不挡路的伤 2/8。图底小字：宿主矩阵含脚手架×模型双变量，不做归因拆分。
- **图型**：大矩阵 / 热力图（手绘感，不要精确比例，传达"大面积无声"即可）。

### 5. eval05-three-factors.svg（全卷核心模型图）

- **支撑论点**：检出率 = 读到 × 愿报 × 挡路，三因子缺一即未检出，且可归因到断掉的那一级。
- **画什么**：三道串联的闸门（或漏斗三段），水流从左向右：①**读到**——伤在 agent 要走的路上吗（失效形态注：T3 型，伤件从未被打开）；②**愿报**——察觉了肯说吗（失效形态注：「察觉了但没报」是最危险的未检出形态）；③**挡路**——说了会停下来吗（失效形态注：检出 ≠ 止损，报了照样跑完）。出口两岔：检出 / 未检出；未检出岔口画一条反向虚线箭头沿三道闸门折返，标「未检出 → 反推断在哪道闸」。图顶公式：检出率 = 读到 × 愿报 × 挡路。
- **图型**：串联闸门 / 漏斗。

### 6. eval06-two-arms.svg

- **支撑论点**：归因靠对照，不靠证据强度；对照组选错比没有对照组更危险。
- **画什么**：上半部正面示范：同一组用例分叉进两臂——with 臂（带插件/skill）与 without 臂（裸基线），两臂分数相减得 Δ = 真贡献，Δ 进报告首页。下半部反例区（打 ⚠）：对照组被污染的三种形态——拿老 profile 当对照 / 对照组靠默认值"自动出现" / 无裸基线直接报分——汇入同一句结论：「没有裸基线时，『全绿』和『没测到』长得一模一样」。
- **图型**：分支对照图（上正反例）。

### 7. eval07-meta-loop.svg

- **支撑论点**：裁判本身也要被校准；误报的价值不在改正，在长出机制。
- **画什么**：一个闭环（四节点环）：观测错误 / 误报 → 产出假结论 → 公开翻案（v1 错误归因原样保留，标注"更正成本=一次尴尬，收益=可信的轨迹"） → 长出新机制（环上挂四个小标签：排除计数 / 判活器自测 / 绝对路径纪律 / flaky 与 error 分账） → 回到起点，下一轮测量更可信。环心一句：**裁判的 bug 比被测对象的更隐蔽**。
- **图型**：循环图（中心句 + 环上机制标签）。

### 14. eval08-quality-cost-frontier.svg（eval08 主图）

- **支撑论点**：只按质量裁决等于给「花钱买通过率」开后门；18/18 打平的臂仍可因更贵被否。
- **画什么**：散点图，横轴=每成功结果成本（美元），纵轴=质量（通过率）。约七八个方案点，连出一条 Pareto 前沿折线；前沿内侧一个点高亮，标签「18/18 全成功，但每 rollout 贵 $0.0648，超预注册门槛 $0.02 → 否决」。前沿上的点标「可讨论」，内侧点标「无需理由淘汰」。角上小字：JevBench 计价按「每 1000 次决策美元」而非每千 token。
- **图型**：散点 + Pareto 前沿。

### 15. eval08-cost-ledger.svg

- **支撑论点**：成本首先是实验卫生问题；零静默重试 + 逐请求授权，账才可信。
- **画什么**：横向账本链：预算池（预注册金额，阀门）→ 逐请求授权（每发一次请求扣一格）→ provider 调用 → receipt（usage 分项：input / output / cache read / cache creation）。链上方画一条打叉的旁路分叉：「超时/503」→「SDK/代理静默重试 ×2」→ ✗（标「重试次数钉死为 0；503 也写『已授权但失败』回执」）。底部两列对照：通胀成本（三份钱记一份）/ 抹平差异（鲁棒性差异被偷消）。
- **图型**：授权-回执流水线 + 废弃旁路。

### 16. eval08-cache-miss.svg

- **支撑论点**：干预的成本不只是自己的 token，还有它顺手作废的那截缓存。
- **画什么**：一条长请求条（总长 400K–850K token 刻度），前段大块标「缓存命中（折扣价）」绿色，末段小块标「新输出」。一次「改 tool_choice」的动作像剪刀一样从中间剪断缓存，后面整条变红标「cache creation 全价重算」。旁注否决结论：「为发一个 76% 概率被无视的信号，打穿全场最贵的缓存 → 否决」。
- **图型**：请求条 + 断点示意（类时序条）。

### 17. eval09-pair-table.svg（eval09 主图）

- **支撑论点**：配对实验的信息只在分歧对 b/c；a、d 不提供信息。
- **画什么**：2×2 表，行=treatment（成功/失败），列=对照（成功/失败）。a 格「都成」与 d 格「都败」灰显；b 格「treatment 赢」绿色、c 格「对照赢」红色高亮加粗，两格之间画一个天平，标「b vs c：零假设下等于抛硬币（exact 二项检验）」。下方小字公式提示：p 值只看 b+c，样本量按预期分歧对数倒推。
- **图型**：2×2 记分表 + 天平。

### 18. eval09-ab-balance.svg

- **支撑论点**：不做顺序平衡，时间漂移会冒充 treatment。
- **画什么**：上下两条时间轴。上轴（正确）：任务对半切，一半 A→B、一半 B→A，AB/BA 色块交错排列，轴上「时间漂移（负载/热更新/判官漂移）」的波纹均匀落在两臂上。下轴（反例，打 ⚠）：全部 A 跑完再跑 B，漂移波纹只染 B 臂，末端冒出一个无法归因的 Δ。
- **图型**：双时间轴对照。

### 19. eval09-proxy-chain.svg

- **支撑论点**：离线显著 ≠ 端到端显著；每个箭头都是一个消费假设。
- **画什么**：五环链：金标排第一 →（被注入）→ 模型打开第一条 → 核实到金标 → 最终答对；每个箭头上写消费假设。链在第二三环之间（「排第一 → 被打开」）断裂、下垂，断点标「模型不按顺序读」。断裂上方挂离线奖牌「15:1，p=0.0005」打问号；链末端挂端到端结果「53→56，p=0.72 → 决策面退役」。
- **图型**：代理链 + 断裂点。

### 20. eval10-three-layer-funnel.svg（eval10 主图）

- **支撑论点**：记忆是写入 × 检索 × 采信三层乘法链，任一层断，下游失败不能归因给上游。
- **画什么**：三道串联漏斗/闸门：①写入（该记的沉淀了吗：覆盖率/关系判定）②检索（金标在第几名：gold-at-1 / top-3 / MRR）③采信（打开·核实·答对）。每层下方画一条反向虚线折返箭头，标「端到端没答对 → 从采信层往回反推断在哪层」。门侧挂真实数字小标签：写入面「咨询 55 次，0 次越阈（未测）」、检索面「0.620→0.495 p=0.001」、采信面「注释臂 34/60 vs 静默臂 42/60」。
- **图型**：串联漏斗 + 折返归因（沿用 eval05-three-factors 同构画法，保持系列视觉一致）。

### 21. eval10-recall-rank-split.svg

- **支撑论点**：「在不在」与「是哪个」必须分家：BM25 地板判缺席，判官只在 band 内排序。
- **画什么**：候选记忆纵向排开，左侧一条词法检索轨道（BM25 读全文），低分区涂阴影标「低于阈值 → 判缺席，不咨询判官（v1 误杀区：480 字节窗口把迂回措辞整片枪毙）」；高分区画一个 band 区间，右侧判官只在带内工作，融合公式标「相关概率 + 0.5×归一化 BM25」。下方两态自适应小图：分数陡（程序性记忆）→ band 收没、退回基线；分数平（事实型）→ band 全盖、判官发挥。
- **图型**：分区轨道图 + 两种分布小对照。

### 22. eval10-shadow-identity.svg

- **支撑论点**：shadow 要过逐字节同一性闸门，不许有「半生效」状态。
- **画什么**：同一输入分叉两轨：shadow 轨（判官照咨询、判断只记账）与 off 轨，两轨汇入一个 `diff = ∅` 的闸门（两张完全重合的文档图标），通过才允许进入 advisory 轨；判官超时/故障/返回「都行」时画旁路：输出保持原始顺序。下方对照组纪律小注：判官接入地址默认导出为关闭态，需要的臂再显式换回。
- **图型**：双轨 + diff 闸门。
