# eval09 · 什么代价——质量与成本的联合裁决

## 定位

eval01 立了四问（能不能做对 / 坏了会不会察觉 / 是不是它的功劳 / 什么代价），第四问至今只有
一句「成本是一等约束」，独立展开预留给了 eval08。本章补的是**裁决与记账**：成本如何进入
go/no-go 决策、成本账怎么记才不污染归因。eval08 将来讲「花掉的上下文有多少真正有效」
（有效窗口衰减），是本章的一个专项，两章互指不互斥（拍板点 1）。

## 核心论点（候选）

1. **只按质量裁决，等于给「花钱买通过率」开后门**：更强的模型、更多重试、更长的上下文、
   更密的自检，都能把通过率往上买；没有成本轴的 pass rate 是单目视觉。
2. 裁决单位是 **cost per successful outcome（每个成功结果的成本）**与边际成本
   （下一个百分点多少钱），不是每轮多少钱；质量-成本是联合裁决，不是两张各报各的表。
3. **成本首先是实验卫生问题，其次才是经济问题**：两臂的 token 路径不一致时，Δ 无法归因；
   静默重试是最隐蔽的成本失真——它同时污染效果与成本两个数字。
4. 美元门槛与停止规则必须**预注册**：全成功但超成本门槛的臂，照样否决。

## 章节结构

1. **开场病例：18/18 全成功，仍然被否决**
   - 【外部·待核验】M 项目 plugin kernel v1 配对实验：两组 18/18 全成功，候选臂每 rollout
     贵 $0.0648，超过预注册门槛 $0.02 → 拒绝（doc/BENCHMARKS.md）。
   - 【亲历】作者侧的对应病例：108 格矩阵每格三跑的真实 token/时间账（eval04 已用矩阵，
     本章只引数字重算「多买一轮复测」的成本）；或 skill-up `--iteration N` 采样
     （eval-series ch02）——为把置信区间压窄多跑的轮次，钱花在哪、买到了什么。
2. **为什么质量单独裁决会出错**：买通过率的四条通道（模型升级/重试/上下文/自检频次）；
   pass rate 对预算单调上升的思想实验。
3. **联合裁决的三个量**：cost/success、边际成本、质量-成本 Pareto 前沿；
   「不差钱的臂」与「便宜但显著差的臂」都可能输，赢的是前沿拐点。
   - 【外部·待核验】JevBench 把 Cost 与 Speed 做成与 Intelligence 等权的几何平均轴、
     成本按「每 1000 次决策」而非每 1000 token 计价、每 10× 扣 30 分
     （fstandhartinger/jevbench README/METHOD）——一个「判官级服务」的公开定价坐标系。
4. **成本账怎么记（上）：逐请求授权与零静默重试**
   - 持久化预算账本、每次调用单独授权；503/配额失败也写 authorized-failure 回执，
     **零静默重试**（M 项目 `WBBENCH_PROXY_MAX_RETRIES=0`，【外部·待核验】）。
   - 重试的双重污染：通胀成本 + 把臂的鲁棒性差异抹平。
5. **成本账怎么记（下）：缓存经济学**
   - prompt cache 是长上下文实验最大的隐性变量；改一次系统提示词注入、动一次 tool_choice，
     可能让整段前缀缓存失效——「最贵的一次干预」。
   - 【外部·待核验】stall gate 否决「限制一轮 tool_choice」方案的理由之一即缓存失效代价
     （doc/STALL_GATE_DESIGN.md）。
   - usage 分项必须分开记：input / output / cache read / cache creation；只报总 token 等于瞒账。
6. **成本作为归因卫生**：两臂除 treatment 外的计费路径必须逐字节对齐；
   对照组若走了不同默认配置（含默认 advisor、默认重试），成本差与效果差同时报废
   （与 eval10、eval11 的污染节互指）。
7. **预注册的美元门槛**：合同里先写「累计授权金额、单样本上限、超支样本归 invalid 还是
   计入、到达门槛后的动作」；【外部·待核验】recall-order 试点累计 $15 授权、shard 顺序
   执行（evals/memory/pilots/longmem-recall-order-glm52-v1/pilot-contract.json）。
8. **收口与接口**：本章管裁决与记账；钱花出去后上下文是否「有效」交给 eval08；
   方法论回扣 eval01 四问地图——四问到此全部有主。

## 配图

# eval10 · 配对实验手册——让同一道题回答两次

## 定位

eval06 立了「归因靠对照」与双臂最低配置、pass@k/pass^k，但**怎么跑一次配对实验**没有
操作规程：全书 grep 不到 McNemar，顺序平衡、无效台账、预注册合同全空。本章是工具性最强的
一篇——目标是读者读完能照着开出一个配对实验。放在 eval06 紧后。

## 核心论点（候选）

1. agent 任务难度高度异质、单次行为概率化，独立两组的 Δ 被任务噪声淹没；
   **配对 = 每个任务自己跟自己比**，把任务间方差从分母里消掉。
2. 配对实验的信息只在**分歧对**里：2×2 表的 a/d（两臂一致）对「有没有差异」不提供信息；
   样本量按预期分歧率估，不按总样本量估。
3. **无效（invalid）不是失败（fail）**：基础设施原因失败的 rollout 必须单列且永不允许
   改判；无效规则先于实验写死，事后放宽校验的重评只能标注「探索性」。
4. 离线代理指标的显著与端到端行为的显著是两次独立审判；每一层代理指标都必须书面声明
   「我在替谁代理、消费假设是什么」。

## 章节结构

1. **为什么要配对**：从 eval06 的双臂图出发；异质任务 + 概率行为下独立两组的失败姿势；
   配对设计的一句话定义（同一 fixture、同一模型版本、仅 treatment 不同）。
2. **配对的最小结构**：
   - fixture 冻结（题面、仓库 commit、scorer 版本钉死）；
   - 全新隔离环境 per 臂（HOME/工作区/记忆库），跨臂零泄漏（与 eval11 污染节互指）；
   - **顺序平衡**：AB/BA 交叉执行防时间漂移（provider 状态、模型热更新、时段负载）；
   - 温度/种子策略写明：不确定就固定可复现项 + 报告不可复现项。
3. **只数分歧对**：2×2 表（a 都成 / b treatment 成对照败 / c 反之 / d 都败）；
   McNemar 精确版（小样本直接对 b/c 做二项检验）；
   样本量直觉：b+c 预期只有几十时结论多稳；Wilson 管单比例、McNemar 管配对差，各司其职
   （接 eval-series ch01 的 Wilson 段，不重推公式）。
4. **无效台账**：503/超时/配额/工具链缺失 → invalid，永不允许变 fail；unscored 永不允许
   变 pass；【外部·待核验】M 项目 W1 三次 503 零 token 挂 Blocked、scorer 基线噪声
   「永远不得作为 agent 结果报告」。
5. **先定规则后看数：预注册合同**，给一页纸模板（附录 A）：
   假设与方向 / 主指标（唯一）/ 臂定义 / 样本量与停止规则 / 预算（引 eval09）/
   无效行规则 / 统计方法 / 顺序表 / 数据封存取回条件。
6. **病例：88/139 判无效之后**
   - 【外部·待核验】recall-order 试点：校验器假设结果行顺序不变，而 treatment 正是改顺序，
     88 行被判无效 → 按预注册「不可解释、不推广」；事后放宽校验重评 125 对，结果 null，
     全程标注「post hoc exploratory」（#244 与试点目录）。
   - 教训：测量仪器自身假设与 treatment 冲突时，正确动作是判无效 + 修仪器 + 重新注册，
     不是捞数据（与 eval03「对测量仪器注入」互指）。
7. **两次显著的断层**：
   - 【外部·待核验】离线金标排序 15:1，p=0.0005 → 端到端核实 53→56，p=0.72；
   - **代理链与消费假设**：「排第一」代理「会被打开」，但模型不按顺序读结果——
     代理在消费行为上断裂；每设一个代理指标，书面回答「下游凭什么消费它」。
   - 【亲历】作者侧同构病例候选：truncation 检出（检出≠告知≠挡路，eval04/05 已立）——
     「检出率」本身就是行为的代理，挡路率才是终点，本章把它抽象成代理链通则。
8. **treatment 的文本纪律**：judge/判官 prompt 措辞是 treatment 的一部分，改措辞等于换药；
   【外部·待核验】同一批题不写 criteria 6/18、写了 17/18（metask-jev README）；
   自家中译：红线写法实验 66.7%→100%（eval02 已用，一句互指）。
9. **收口**：配对不是目的，可归因才是；手册清单并入 eval07「错误→机制化」总单。

# eval11 · 记忆怎么测——从「被注入」到「被采信」

## 定位

作者最独特的交叉章：RAG 书 23 章讲检索本身、界面第 22 篇讲记忆的产品形态与「生效配置
预览」之缺，**没有一篇讲 agent 长期记忆系统怎么做效果评测**。本章把 RAG 的检索评测法迁到
agent 记忆场景，并补上检索之后的两层（注入、采信）——这是传统 RAG 评测没有、而 agent
记忆独有的断裂高发区。

## 核心论点（候选）

1. 记忆系统是一条三层乘法链：**写入（该记的记了吗、关系判对吗）× 检索（金标在第几）
   × 采信（模型打开、核实、答对）**；任何一层断裂，下游失败都不能归因给上游
   （eval05 乘法模型在记忆域的重演）。
2. **「被注入」不是终点，甚至不是好信号**：注入率/排序分是行为的代理，主终点必须是
   「打开并核实到金标 + 答对」；记忆评测最容易自欺的地方就是停在第一层。
3. **召回与精排必须分家**：「答案在不在」与「是哪一条」是两个机制；弱判官 + 自由召回
   会成片枪毙措辞迂回的真相关；语义判官与词法检索互补而非替代。
4. shadow 的字节级同一性是记忆实验的因果地基：不开功能的轨迹必须逐字节相同；
   对照组环境里默认 advisor 必须显式关闭——记忆系统是默认值污染的重灾区。
5. **写路径的评测要先造题再开功能**：造不出能触发关系判定的 fixture，功能就永远停在
   「未测」——「未测」不是「证伪」。

## 章节结构

1. **开场：RAG 评测迁到 agent 身上之后多出来的两层**
   - RAG 书的传统终局（检索到 + 生成对）在 agent 记忆里不够：中间隔着「宿主注入哪几条」
     与「模型真的去读哪几条」两个自主决策。
   - 【亲历】从作者 RAG 书取一个检索金标病例压缩成两段，论点是「同样的金标，在 agent
     里多了两环」（RAG 书互指不重讲方法）。
2. **三层指标链**：
   - 写入：覆盖率（该沉淀的事实沉淀了吗）、关系判定（同义/矛盾/枚举意图）；
   - 检索：gold-at-1、gold-in-top-3、turn 级原子记忆库 vs whole-session 会话库
     （两库难度与答案形态不同，必须分报）；
   - 采信：打开率、打开后核实到金标率、最终答对率；
   - 三层各自的分子分母与归因折返规则（沿用 eval05 口气）。
3. **金标与封存**：dev/holdout 分离、holdout 在读题面前冻结；
   - 【外部·待核验】LongMemEval（公开学术 benchmark，可优先升级已核验）；
   - 与 RAG 书的 holdout 纪律、eval07 校准集保质期互指。
4. **召回与精排分家**：
   - 词法地板判「缺席」（top 分阈值以下不注入也不咨询）、判官只在 BM25 带内排序；
