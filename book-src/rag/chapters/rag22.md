# Query 理解：从那句话到检索动作

> **待办（2026-10-14）· 待写**：本篇是成册时确认的内容缺口——七步链路里唯一没有专篇的两环之一（另一环是生成层，见「从能跑到能扛」卷第 07 篇）。全系列把五篇的密度堆在检索这一环，检索前发生了什么却只在各篇里零散提过。

> 这一篇的说服力来自「我踩过」，只能由作者写，不由整理生成。以下是待写内容清单（素材出处已标原篇号，按册内章节号互指）。

## 待写清单

1. **约束提取**——从 query 里解析年份、期间、口径、电压等级这类强约束。接「检索的错觉」卷第 02 篇（原 #06）四层解法的第一层：metadata 预过滤的前提就是这里抽得出约束。抽不出时的三种降级策略（默认值 / 模糊优先 / 上下文继承）也在那一篇，本篇接住「上下文继承」的实现。

2. **意图分类**——判断用户在问数字、问原因、还是问风险，据此决定去哪个 section 检索。接第 06 篇（原 #10）的 section-aware retrieval，那一节只说了 section 有用，没说分类怎么做。

3. **改写三件套**——Multi-Query / HyDE / Step-Back，各自的适用场景和代价。原 #09 埋过一句「改写错了会把 query 带偏」，本篇展开。

4. **改写什么时候不该上**——小库、query 类型单一时，改写的增量可能抵不过一次 LLM 调用的延迟和漂移风险。

5. **指代消解与多轮**——「那个跳闸的」「毛利呢」这类 query 怎么继承上一轮约束。原 #06 提了思路，没给实现。

6. **与生成层的分工**——哪些歧义该在检索前问清楚，哪些该在生成前反问用户。原 #15 第八步（query 语义歧义）的落点在这里。

- 每个手段必须给「什么时候不需要它」。
- 数字、延迟代价按自有库口径标，不引用通用评测数字。
