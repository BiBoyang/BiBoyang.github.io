## 一、开场：前七篇测自己，这篇测别人

- 系列一句话回顾：测自己的插件/skill/CLI，方法论问题是「假通过、观测骗人、考题骗人」（呼应 3/5 篇）

- 关键差异一句话：**测自己的工具有 spec，测别人的生态没有**——oracle 的缺席是后面所有故事的源头
- 预告三个方法论问题：oracle 从哪来 / 锅怎么分 / 分母是谁
- 系列弧可点一句：第 5 篇测「流」、第 7 篇测「文件」、本篇测「生态」——同一套检出思想的三次迁移

## 二、分母是谁：采样的幸存者偏差

- 你只能测「装得上」的；社区实测 9247 候选 → 六成装得上（AdamPlatin123 容器真装数据）
- 高星 ≠ 可测：热度榜头部一半是 UI 类（桌面壳/皮肤/TUI），headless 下结构性不可测；破甲/红队类主动剔除（定位风险）
- 选品三原则：headless 可测、类型覆盖（管线型/工具型/编排型）、版本钉死——三个插件恰好对应三种 oracle 形态
- 引出「四层漏斗」：人气 → 可装 → 行为正确 → 故障韧性，每层都有真实失败可讲（放漏斗总表）

## 三、L1 可装层：安装不是前置条件，是第一层数据

- **npm 同名错位**：npm 的 `dsh-routing-suite@0.1.2` 指向 dragonbaba 账号，不是那个 7000★ 仓库；裸名 modsearch 同样中招——「装错对象」是生态级风险，安装指引必须全限定
- **7000★ 装完即死**：routing-suite 命令成功但 injector/lib 缺失——prepare 构建被 pnpm 11 默认拦截；作者 README 自己写着「github: 装配由 prepare 钩子自动构建」——设计没错，是 pnpm 把路从脚下抽走了（呼应第 4 篇「环境在变」）
- 解锁过程一句话带过（allowBuilds 混合方案），重点是**安装成功率从此成为漏斗第一层，而不是测评开始前的 silent filter**
- console 块候选：install 成功但 lib 缺失的对比证据

## 四、L2 行为层：oracle 从哪来

- 没有 spec，oracle 三个来源：README 承诺（测承诺）/ 首次行为钉版（测回归）/ 宿主不变量（测相容性）——三层抓不同的虫，措辞要不同的谨慎
- 三种形态各一例：routing-suite=行为规则断言、modlens=工具输出结构断言、agent-teams=trace 事件序列断言
- **「不可判定」纪律**：modlens 视觉成效层写不出可判定断言（本机无可用 vision 引擎）——如实标「不可判定」，不写橡皮图章断言；这是第三篇「证据质量不保证结论正确，保证纠错速度」的应用
- agent-teams 的正面案例：自带 `verify:harness-contract` 验证链——高星插件里少见的自带验证，全绿有原因的

## 四·五、原则分层：第 1 篇说过「不用替身」，这篇为什么又用了（必写，防老读者挑刺）

- 第 1 篇原话：「读真实 trace，不用 LLM 替身……替身测通过的系统上线照样崩」——那是**行为语义**场景的立场（prompt 组装、工具协议、模型行为不能被换）
- 本篇与 5/6 篇的 mock 是**协议故障注入**：模型智力无关，要的是逐字节可控的故障（真实模型不会按要求截断）
- 四层漏斗就是这个分层的具身：L2 冒烟走真实 API（行为），L3 chaos 走 mock（协议）；mock 的保真风险由黄金样本校准兜底（第 6 篇机制）
- 成本对照数字：第 1 篇 12 条用例约 12 万 token；本轮真实 API 部分合计 20116，chaos 层为零

## 五、L3 韧性层：chaos 是归因工具，不只是压力测试

- 裸 chaos 基线（v0.5.0 固化）vs 挂载 chaos——对照组思想：挂载后宿主行为变了，账才算到插件头上
- routing-suite 解锁后四格全过、与裸基线一致：7000★ 插件不破坏宿主故障处理——「全绿也是结论」
- once/match 语义在编排插件下的压力（agent-teams 多并发 LLM 请求），一句话带过

## 八、沉淀：生态评测的四条纪律（读者能拿走的）

1. **分母写出来**：采样框、安装成功率、剔除名单全进报告——结论只对「可安装的头部」成立
2. **oracle 分三层**：承诺 / 钉版 / 不变量，写不出可判定断言就标「不可判定」
3. **归因先跑裸对照**：红格没有对照组不许下结论；对照组选错比没有对照组更危险
4. **成本透明**：版本 + 测试日期 + token 开销（本轮真实 API 合计 20116）进每份报告
