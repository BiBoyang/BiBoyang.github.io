> 私人笔记。假设面试官认真读了 7 篇（第 8 篇未发布），推演他会从哪里进、沿什么链往深挖、哪里会把人问住。每条路线：**入口问法 → 深挖链 → 好答案的骨架 → 你的弹药 → 危险区**。

# 面试官的第一反应

抓住眼球的东西，也就是他问题密度最高的地方：108 格矩阵和那个「差点发布的错误结论」；TOCTOU 并发 bug 全过程（含 48 启动崩 23 的复现统计）；给自己挖坑又自己填的误报记录（第 3、4 篇）；第 1 篇里的统计硬货（无偏 pass@k 估计、单侧 Wilson、Jensen）。同时他心里立了几面红旗：**N 小、模型变量混杂、judge 校准立了法没带数字、个人项目 n=1**——好的面试官不会直接打红旗，会顺着红旗往下挖，看你自己知不知道。

# 路线 A：统计与口径（从第 1 篇进）

**入口**：「你说判置信区间不判点估计，展开讲讲？」

**深挖链**：
1. 为什么单侧 Wilson 而不是 Wald？→ 2. Wald 在什么条件下失效？（小 p 小样本系统性偏窄）→ 3. 白板推一下 pass@k 的无偏估计为什么是 1−C(n−c,k)/C(n,k)，为什么 n=k 时套 1−(1−p̂)^k 有偏？→ 4. 你的 harness 里 12 条用例、每条 3 次，这个样本量下你的 Wilson 界大概多宽？这些「过线」结论还站得住吗？→ 5. flaky 用例你判 pass 还是 fail，治理逻辑是什么？

**好答案骨架**：三个量分开（定义 / 估计 / 门禁判据）；为什么 pass^k 用 C(c,k)/C(n,k)（x^k 上凸 → plug-in 向上偏，能给 n=3,c=2,k=2 的 4/9 vs 1/3）；遮羞布（重跑）和尺子（trials）分家是显式设计选择；诚实承认 12 条用例的统计功效就是不够——所以报告带 n、结论说「稳定/概率性/稳定漏检」三档而不给精确概率。

**弹药**：第 1 篇 §四「把遮羞布和尺子分开」；第 7 篇局限一节（x/N 不应被读作比率估计）；第 5 篇「每格 3 次全一致」靠确定性注入而非统计功效。

**危险区**：现场推导卡壳（组合估计的推导要能空手写出来）；被问「你的 judge TPR/TNR 是多少」——系列里立了校准纪律但没有自己套件的实测数字，这是最实的窟窿（见文末五问）。

# 路线 B：实验设计（从第 2、5 篇进）

**入口**：「with/without 对照听起来简单，你怎么保证对照组真的干净？」

**深挖链**：
1. 宿主环境污染有哪些载体？（skills 自动发现、hooks、AGENTS.md、env、全局配置）→ 2. 你怎么发现 skill 根本没注入的？（翻会话落盘找 skill 名零出现——直接证据不是退出码）→ 3. 截断矩阵里 F5 为什么是阳性对照？为什么对照要细到协议事件名？→ 4. mock 的方言你怎么保证和真实 API 一致？（黄金样本对齐）→ 5. Claude Code 那列实际跑在 DeepSeek 上，「宿主间差异」的结论你怎么归因？

**好答案骨架**：对照组的「无」必须被强制出来；送达证明把「工具没反应」和「故障没送达」分开；「不可判定」如实标注而不是橡皮图章；混杂变量主动承认（脚手架和模型两个变量变化，差异不做归因拆分——原文就写了，照原文说反而加分）。

**弹药**：第 2 篇三种沉默失败 + crontab 事故；第 5 篇翻案节；第 6 篇三次口径修复；第 7 篇「宿主可见路径不得编码伤型」红线。

**危险区**：claude F2 那格（L0、无恢复、无标——四工具唯一交付了半截答案的格子）正文没解释，被追问「为什么 F2 没像 F1/F3 那样重试」要有答案或诚实说当时没查；「三个独立 agent 复核」的独立性会被追（同模型家族盲区相关——你自己第 1 篇就写过 subagent 裁判的相关盲区）。

# 路线 C：系统设计开放题（白板，综合全部）

**入口**：「给你一个新的 agent CLI（或：一个内部 skill 平台、一百个第三方 skill），从零建评测体系，预算有限，你怎么排优先级？」

这是最能拉开差距的一题，答案就是那张全景地图：

1. **第 0 站先做**：trace/落盘第一天进代码，格式带版本号——拖久了只能对着线上系统逆向工程成功标准（Anthropic：20–50 个任务就足以起步，越晚越难）
2. **用例从真实失败反推**：先 error analysis 再写 eval，不为想象中的错误建评估器
3. **门禁最小闭环**：确定性断言守 CI（毫秒级、零 token）、judge 延后到有校准集再上、成本分层
4. **对照与隔离**：工作区/session 根/宿主环境三件套，隔离等级按最坏行为定
5. **故障注入后置**：先保证行为回归，再做协议故障的 mock 和送达证明
6. **meta 一开始就埋**：判活器自测、排除计数、报告 schemaVersion——裁判的 bug 比被测对象的更隐蔽

**深挖链**：「token 预算每月只有 X，怎么分配？」→（L4 真跑限量 + L3 替身全量 + 采样策略）；「模型每周更新怎么办？」→（版本留痕 + 重校纪律 + 能力/回归分家）；「怎么向上解释这套东西的价值？」→（桥梁指标/伤亡半径分层，别拿门禁绿直接兑业务承诺）。

**危险区**：堆功能不排优先级；答案里没有成本数字（你自己每篇都写 token 开销，面试里也要随口能报）。

# 路线 D：事故深挖（behavioral + 技术，从第 1、3、4 篇进）

面试官挑一篇，让你完整讲一次定位链，然后专打推理环节：

- **TOCTOU**：「你怎么从两条 ENOENT stderr 确定是竞态而不是安装损坏？」「lstat→readlink→unlink 序列里第二个后果（A 删掉 B 刚建好的链接）你当时怎么确认的？」「三个 agent 复核为什么必要，它们真的独立吗？」
- **误报（第 3 篇）**：「你犯了两个观测错误，根因上有什么共同的？」「如果当时没有那条 verbose 日志，什么机制本可以更早抓住？」（答：排除计数/产物对账的本该存在——后来你确实把它做成了机制，这是最好的答案形态：错误→机制化）
- **CI 红（第 4 篇）**：「为什么第一反应是平台差异？确认偏差在你的排查纪律里怎么防？」「GitHub 构建合并态这个机制，除了导致这次误诊，还意味着什么？」

**好答案骨架**：定位链按「现象 → 假设 → 最小反证 → 修正」讲，主动说出哪一步走了一小时弯路；每个事故结尾落在沉淀的机制上（排除计数、判活器回归、绝对路径纪律）——**面试官要的不是你没错过，是错了之后长出了什么**。

# 路线 E：批判与边界（压力位）

**入口**：「你这套东西的局限是什么？如果我是你的 reviewer，我最该挑战哪一条？」

典型攻击点和应答：

- 「replay 便宜稳定，你的全真实重跑贵且抖，为什么你是对的？」→ 不是谁对，盲区互补：replay 冻结工具观测，TOCTOU 在回放里物理不存在；真实重跑保留时序但低概率竞态可能样本内不触发。按场景选，别传教。
- 「N=8/3 也敢画表？」→ 承认只能分「稳定/概率性/稳定漏检」三档，x/N 不作比率估计，原始数据口径全公开；REPLICATION.md 是给别人的复现手册——把「别人验证过吗」变成「你可以自己验」。
- 「个人项目，一个人的标准，凭什么说团队该这么干？」→ 美团「1 个独裁者」恰好在说团队也需要拍板者；你的框架诚实标注了「标准由我定在个人尺度成立」。
- 「这和 Anthropic/Hamel 的公开方法重叠度多高？」→ 诚实切分：校准纪律、error analysis、套件生命周期是业界共识（带出处），自己的增量在——协议故障注入下沉到截断/skill 完整性这类「内容层残缺」、误报与翻案的完整过程记录、检测率由「伤的位置」决定这个发现。

**危险区**： defensiveness。这条路线考的就是你对自己红旗的态度——你的博客已经用第 3 篇证明了你会公开推翻自己，面试里保持同一姿态即可，千万不要在面试里变得比博客里更爱惜羽毛。

# 路线 F：认知与延伸（聊想法）

- 「agent 评测和传统软件测试的本质区别？」→ 判定对象分两层（对话记录 vs 终态）；非确定性让「同一输入同一输出」的断言失效，断言目标从结果移到路径覆盖+终态；成本成为一等约束（每个样本都是真钱）；模型版本是环境变量不是常量。
- 「模型越来越强，这套工具链哪些部分会贬值？」→ judge 校准会简化但统计口径不会；红线用例会随能力提升失效（eval saturation，该剪）；「检出靠排除不靠默认」这类协议层纪律与模型能力无关——截断矩阵里最强的 codex 也只是恢复得快，transcript 依然零打标。
- 「评一个你看不到内部的闭源 agent 呢？」→ 只剩黑盒手段：协议故障注入 + 终态对照 + transcript 打标检查——正好是你第 5/6 篇的方法。
- 「下一步做什么？」→ 有真实答案：judge 校准实战数字、宿主矩阵原生 Claude/GPT 列复现、编排级 chaos（已被源码阅读砍掉一次——「先查源码再决定烧不烧 token」本身就是好答案）。

# 最可能被问住的五个点（提前准备）

1. **「你的 judge 校准数字呢？」**——系列立了 TPR/TNR/校准集纪律，但没带回自己套件上的实测。最实的准备：真跑一次，几十条、亲手标、报 TPR/TNR/Wilson 界。这一条补上，整个系列从「立了法」变成「执了法」。
2. **白板推导**——pass@k 组合估计、单侧 Wilson 公式、Jensen 偏差方向，三个要能空手推。推导过程比结论重要，第 1 篇原文就是你的讲稿。
3. **混杂与 N 小**——宿主矩阵模型混杂、N=8/3、单条件样本。准备口径：原文怎么声明的就怎么说，附 REPLICATION.md 的存在和未完成状态。
4. **「被独立复现过吗？」**——开源包存在，但截断矩阵、skill-quake 的核心数字都是你一人跑的；「另一个 kimi-code 会话独立跑通 skill-quake 矩阵」算半个证据（方法论可复制性），诚实分级回答。
5. **规模化与成本**——「12 万 token 一轮、每周模型更新、团队十个人，这套东西经济吗？」——准备成本分层（确定性守 CI、judge 守 prod、采样策略）和「能力/回归分家 + 剪枝」的治理答案。

# 快问快答卡

| 问 | 一句话答 |
|---|---|
| pass@k vs pass^k | 至少成一次的概率 vs 全成的概率——重跑治理 vs 可靠性度量，故事相反（0.75 → 1.0 vs 0.056） |
| 为什么单侧 Wilson | 「缺陷率是否低于阈值」是单侧问题，z=1.645，小样本比 Wald 稳 |
| F5 为什么是阳性对照 | 必然触发 kimi 底层空响应重试，测不出它 = 注入链路坏了，阴性结论作废 |
| TOCTOU | 检查（lstat）和使用（readlink/unlink）之间的竞态窗口 |
| Hyrum's Law | 可观测行为足够多就总有人依赖，不管你承诺过什么——断言职责不断言字段 |
| 假通过最阴的一种 | 干预根本没注入：断言跑在一个从未发生的实验上 |
| mock 最大的坑 | 方言说错制造假阴性；mock 权威性和客户端严格性成反比 |
| judge 第一纪律 | TPR/TNR 分开看，总一致率会被多数类淹没 |
| 门禁的本质 | 反馈回路不是判官：追求永远不跑偏太远，不追求一次判对 |
| 这套体系的元原则 | 裁判本身也要被校准——每篇的 bug 都不在被测对象，在测量系统自己 |

# 收尾：你的最大优势和最大风险是同一个

这套博客对面试的最大价值，是它证明你**把错误当作一等素材**：误报发更正、翻案保留废案、归因文件保留 v1。这在候选人里极稀缺。风险也在这：博客越诚实，面试官越会拿同样的诚实标准要求你本人——面试里对红旗的每一次遮掩，都会和博客里那个自己推翻自己的人设打架。保持同一姿态，弱点点名承认加改进计划，是唯一和这套材料自洽的答法。
