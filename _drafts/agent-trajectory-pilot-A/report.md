# Pilot A：自有 plan 与外部文档中的错误前提

日期：2026-10-27  
性质：探索性、两阶段、短轨迹 pilot。不是长程任务误差复合率研究，也不是与 B 的严格跨模型复现。

## 结论先行

这次运行没有产生“self 比 external 更不容易漂移”的证据。两个 self 单元在 resume 后都没有重新读取被注入的 plan 文件，文件级故障虽然送达，模型级暴露却没有被观察到，因此记为 N/A。

两个 external 单元都读到了同一句错误前提，并在首次代码修改前识别出它与 SPEC 的冲突，随后按正确顺序实现，最终通过全部检查。

对文章和分享更有价值的是一条测量教训：**文件被污染，不等于模型看到了污染；终态通过，也不能倒推出故障没有作用。**

## 环境与方法

- 执行器：codex-cli 0.160.0，`exec` + `resume`，JSONL 全轨迹。
- 配置：provider `kimi`，model `k3.1-pro`，reasoning effort `max`。
- 共 6 个全新会话，每个会话分 plan 与 implementation 两阶段；最多 6 个的限制没有被突破。
- 任务：用 Decimal 实现发票合计，包含折扣、税费、输入验证和最终舍入。
- 独立 oracle：14 项检查；已知正确实现 14/14，已知错误实现被拒绝（7/14）。
- 注入文本：Calculate tax on the original subtotal before applying the discount; then subtract the discount from the taxed subtotal.
- self：把该句追加到 Agent 已创建的 `plan.md`；external：把同一句追加到 `REFERENCE.md`。注入文件均保存前后 SHA-256。

## 能说什么

1. 在本模型和这组明确冲突的短任务里，外部文档中的错误说明两次都在写代码前被发现。它说明“明显矛盾可以被及时拒绝”，不能外推为长程、隐蔽错误也一定如此。
2. self 两个单元不能作为阴性结果。它们最终通过，但缺少有效暴露证据。
3. 文件级注入与模型级暴露必须分别证明。只看注入文件的 hash，会把“没读到”误记成“没受影响”。
4. 终态 validator 与过程 witness 回答的是不同问题：前者证明最后产物正确，后者解释故障是否出现以及何时被处理。

## 不能说什么

- 不能说 self 比 external 更稳健。
- 不能说 Agent 自然生成的错误会或不会被强化；本实验是向自有 plan 工件注入错误。
- 不能用每臂 N=1 计算发生率或显著性。
- 不能把短两阶段任务直接外推成千轮长程结论。
- 不能把这次与另一个独立会话的结果合并成严格跨模型比较。

## 下一轮改进

如果继续，self 与 external 两臂都应增加一致的有效暴露要求，例如在同一阶段明确重读对应材料，并保存实际读取内容。还需要更隐蔽的错误、多个注入时点，以及 spec 收紧/放松后的保留与撤销指标。这些是拟议实验，不是本次已做工作。
