## 1. 篇一《Agent 的中断面》

### 标题候选
1. Agent 的中断面:七种突然停,和它们各自欠的交代
2. 你的 Agent 是怎么停的:七族失败与四种时钟
3. 戛然而止:一份 Agent 中断分类学
4. Agent 耗尽 token 之后(最短,但只覆盖引爆案例,盖不住七族)

### 提纲(目标 6-7k 字)

**§0 面试题(开场钩子,约 600 字)**
- "Agent 耗尽 token,要不要给用户一个输出?"——面试造火箭入职拧螺丝;面试官可能刚跟 GTM 吵完架。【转述】
- 两个真实产品的分岔:WorkBuddy 配额降级四件套(交代/禁止/降级/建议)vs 千问办公(断了引导充值)。【转述】
- **先亮论点再拆题**:这道题问错了主体——"给不给输出"之上还有一层:**任务停了之后,它的"继续合同"是什么**。输出只是继续合同的用户可见投影。

**§1 拆题:两分法不够(约 800 字)**
- 通行拆法:上下文满 vs 配额尽——对了一半。
- 第三把刀(网友补充):网络断。感知上和配额尽同构(进展消失),架构上几乎相反——**配额尽是任务真的停了,网络断是任务可能没停、只是你看不见**。
- 引出分类轴:任务还活着吗 × 状态在谁手里 × 恢复合同;关键变量 = 每种停止原因配什么恢复时钟。
- 首个【源码】证物定调:UsageLimitReachedError 字段表(error.rs:643-649)——resets_at 是数据不是文案;Reserve 场景的商业文案长在 Display 实现里(error.rs:651-657)——**商业闭环和状态机在同一个类型里**(回扣千问:不是商业必然,是没把恢复时刻建出来)。

**§2 七族失败×四种时钟(主体一,约 2200 字)**
- 总表开路(配图文字稿已有)。
- 每族一段,统一句式"**最容易被漏的设计**":
  - A 自愈:自愈机制自己也会失败——恢复消耗的正是引发失败的资源(token);
  - B 墙钟:恢复依赖故障本身(OAuth 刷新要走网络)——共因失效长得和配额尽一模一样;
  - C 等人:等人的状态没人知道——无超时阻塞、UI 断连不清 pending【源码】;
  - D 换路:失败瞬间一切正常,坏的是世界变了(模型下线/上游改版)——没有钟,必须声明替代路径;
  - E 自停:被误当 bug 的正确行为——熔断 3/1【源码】、"拒绝不进上下文";
  - F 载体死:系统自己杀自己(daemon 自更新重启)【源码】;磁盘满杀死的正是 write-ahead 纪律本身;
  - G 僵尸:唯一**不产生错误事件**的失败——审批应答方死了没人知道;exec 侧有钟(GNU 124 退出码、timed_out、"timeout_ms is too large"=**钟也有钟**)【源码】,MCP 调用点存疑(见待办)。
- 网络断三个断面收在 F/G(南向断=重试梯"Reconnecting 3/5";北向断=通知丢弃、状态可重取;进程死=半截 turn 投影 Interrupted);三层状态分布的深潜留在主文 v2,一句互链。

**§3 中断面六要素+1(主体二,约 1500 字)**
- 六要素:停止原因枚举(强类型含恢复时刻)/中断点持久化时序(先落盘再终态)/恢复合同(谁、何时、保什么 ID)/给人的输出/给上下文的输出/防循环约束——外加必填字段:**恢复时钟类型**。
- 点题"应用架构 ≠ agent 架构":六要素横跨协议、持久层、UX、商业——没有一条住在 agent loop 里。
- codex 自身没填满的两处 → "设计题"第一次显形:配额路径无模型可见收场标记(用户中断有、配额没有)【源码】;审批无超时。
- **检验句**:对每一种"突然停",用户和下一次会话的模型,能否各自回答"什么时候、怎么继续"?答不出 = 中断面没设计完。

**§4 收束:回答回那道面试题(约 600 字)**
- "面试标准答案"升级版:先拆族,再按族配时钟;WorkBuddy 四件套是 C 族的局部解;千问缺的不是总结,是继续合同——而"还差 20%,配额刷新后从这里继续"恰恰是转化率更高的商业文案。
- 预告篇二:每一族的钟归谁、怎么设计。

**配图(篇一)**:七族×四时钟总表;可选"三个断面"示意图(南向/北向/进程死)。

## 2. 篇二《恢复的设计》

### 标题候选
1. 恢复的设计:谁持有 Agent 的时钟
2. 自愈不是兜底:Agent 恢复机制的五条纪律
3. 会自愈的系统怎么死(最挑,需副标题兜住)

### 组织轴(全文贡献点)
七族按钟的持有者聚成四对,每对是同一持有者的两种形态——**引擎的钟**(修/停)、**世界的钟**(等/换)、**人的钟**(等待/决策)、**载体的钟**(真死/假活)。

### 提纲(目标 8-9k 字)

**§0 自愈≠兜底(钉概念,约 600 字)**
- 兜底 = 接住并接受岔路(WorkBuddy 降级本地实现);自愈 = 带判定条件的主动修复,目标是**回原路**(压缩换模型还是为了完成原来那次压缩)。
- 栈位:主路径 → 自愈 → 兜底 → 人;真兜底是人——不消耗 token、失败模式无害的最外层 healer。
- 一句版全文纲要:"自愈不是兜底,是有界的主动修复:双时钟、条件重置、出口上住着清理和语义;套娃的截断靠每层更简单,最底层的 healer 是人。"

**§1 引擎的钟(A+E:修与停,约 1800 字)**
- 修:重试三前提(时间过/状态变/换人);双时钟(次数上限 + 绝对时限,blade-code 先例【转述】);条件重置——`history.remove_first_item(); retries = 0;`【源码 compact.rs:324-326】,预算清零只在状态真实变化时。
- 停:自停是设计内的正确行为——guardian 熔断 3/1、fail-closed 90s 超时升级、SessionBudgetExceeded 快速失败【源码】。
- 深水区:自愈的递归——自愈机制自己会失败;四个标本(压缩失败于压缩/换失败域/谁审查审查者/地基级共因);三终止器(换域/降级到人/无代价重跑)。
- 设计题:机器自裁的判定权写进类型,不写进 prompt。

**§2 世界的钟(B+D:等与换,约 1500 字)**
- 等:恢复条件做成强类型数据——resets_at/plan_type/限流快照【源码】;"什么时候能继续"是数据不是文案;沉没进度 vs 沉没成本(转化率论证:断点即卖点,前提是恢复合同存在)。
- 换:路径做成可换的数据——模型目录(内置兜底 + 服务端下发,ETag/TTL)【源码】、压缩换模型【源码】、可插拔执行器(exec-server LOCAL/REMOTE)【源码】。
- 设计题:声明替代路径是架构责任,不是运维动作。

**§3 人的钟(C:等人不挂死,约 1800 字)**
- 全系列最 agent 特有的一节:human-in-the-loop 的持久化语义。
- 现状解剖【源码】:审批无超时 oneshot、纯内存不落盘、断连不清 pending、重路由 = resume 时重放——单机桌面的合理省略,如何变成手机遥控场景的挂死。
- 设计件清单:pending 持久化 / 超时语义(超时后升级给人,不是静默)/ 重路由(任何连接可应答 + 决议广播)/ 决策阶梯(GuardianUserAuthorization ≈ 风控 step-up authentication)【源码】。
- 与主文互链:主文有审批异步化方案 C 的协议草图,本节讲产品无关的设计模式,不重复协议细节。
- 商业面:充值/升级是"人的钟"最常见的形态——断点即转化点,但前提是恢复合同存在(回扣篇一千问案例)。

**§4 载体的钟(F+G:真死与假活,约 1800 字)**
- 真死:先落盘再发请求【源码】、半截 turn 投影 Interrupted(投影层改标、不写回 rollout)、保 turn ID 的 RecoverTurn(引擎备好、应用未接——半成品设计)【源码】;daemon 自更新"装更新→验证→重启→移交"【源码】。
- 假活:僵尸——不报错的失败;exec 侧的钟(124 退出码 / timed_out / async_watcher / "timeout_ms is too large"=钟也有钟)【源码】;cancellation safety 时代的新漏法(await 后的清理永不执行,只有 Drop 会跑)。
- 设计题:每个 await 造钟;超时本身要有上限。
- 【待办】MCP requested_timeout=None 核验后再决定反例能否入文。

**§5 收束:出口清理 + 递归的终点(约 1200 字)**
- 时限出口是清理能发生的前提——无界系统走不到任何出口;G 族僵尸的本质不是"清理漏了",是"出口永远不来"。
- 清理 = 选语义:中断清审批按 Abort 消化而不是合成拒绝("interrupted turns do not continue on a synthetic denial")【源码】——资源泄漏看得见,语义泄漏看不见,后者更毒。
- 信念→数字(出口断言"活定时器数 = 0")vs 信念→类型(RAII/Drop);断言只对执行过的路径说话 → 故障注入是扩界工具【实践 skill-quake】。
- 递归终点:性质递减(每层更简单更弱),最底层 healer 是人。检验句回环篇一收全文。

**配图(篇二)**:四种时钟持有者(引擎/世界/人/载体 × 两种形态);三层结构图(主路径→恢复层→清理层)。
