同一个星期里，同一个病，两个互不相识的维护者开出了两种方向相反的药方。

10 月 17 日，metacodes 的维护者 wayfind 在 issue #277 里公开承认：现行 goal 在连续运行一周以上、迭代上千轮的长任务里，"目标已经影响到代码继续演进"。他预告的根治方案是依托 TinyKG 图数据库把任务逐层分解，每轮注入上下文的除了当前任务，还有"DAG 上目标节点到当前节点的摘要"。

同一周，我把同一个问题拿去问了 LoopX 的作者：层级摘要逐层蒸馏后丢约束、放松验收，怎么发现？他回了我五条机制，每条都挂着 pin 到具体 commit 的源码链接。

一周后，#277 关闭了。goal 和 swarm 分别随 AgentCore Revision 23、24 落地，而长程那部分被明确拆了出去——"a separate design and evaluation effort"，DAG 还没有自己的 issue，更没有 PR。LoopX 的答案则已经在 main 上跑着了。

上一篇《千轮之病》解剖的是病本身。这篇讲两种药方。我把两边的源码都读了，读完发现一件预告里没人提的事：**两种药方的坑，是同一个**。

## 一、先把病说到机制层

这个病为什么存在，Codex 的 goal 扩展源码（约三千行 Rust）给了最清楚的标本。它的自动续跑，本质是每轮重注入一份 `<objective>` 包裹的目标全文，配一整套审计软约束（标 complete 前要逐条找证据、不许用更窄的方案替代目标）和预算硬机制（目标存数据库、模型没有"停下"这个选项、token 记账排除缓存命中）。

这套设计在百轮内是好用的，因为它的一切保证本来就**以会话为边界**：目标是锚，会话是锚的绳长。问题在于同一个注入物被拉到周的尺度之后会发生什么——顶层目标全文逐轮压进上下文，而工作早已深入某个子系统。锚没有跟着船走，于是锚变成了压舱石。

这个尺度上的公开承认有多稀缺，值得单独说一句。我查过一圈公开记录：明确把 goal drift 列为自家首要失效类的是 Devin；OpenAI 和 Anthropic 能看到的公开动作都还停留在会话尺度。千轮以上、公开承认症状并且预告根治方案的，wayfind 那条 issue 是我见到的第一例。

## 二、药方 A：改变注入物的结构

metacodes 的路线是：既然全文注入会压顶，那就改变注入物的结构。TinyKG 把任务逐层分解成 DAG，每轮注入的从"顶层目标全文"换成"当前任务 + 根到当前节点的路径摘要"——模型只看路径上的相关切片。

这个方向在行业地图上不孤独。最接近的现成原型是 Mage（arXiv 2606.06090）：两层状态树，顶层在子目标与决策边界生成摘要——几乎就是"当前任务 + 路径摘要"，连摘要的触发点都一样。

但它有两个已知的无人区，上一篇我写过，这里重述一遍：

1. **层级摘要的保真度没有评测方法。** Mage、HORMA 这类层次摘要工作全都假设摘要是好的，没有失真检测器。DAG 化的本质是把"每轮注入原文"换成"每轮注入蒸馏产物"——每层蒸馏丢了什么约束，目前没有任何检测手段。
2. **replan 语义是空白。** 父目标变更后，已展开的子树如何失效、如何对账，论文和 Devin 都没有公开解法。

截至写稿，这个 DAG 方案的状态是：病被承认，药方画好，evaluation 被承诺——但尚未开工。这不是批评，是时间戳。

## 三、药方 B：让摘要不当权威

LoopX 作者给我的回答，核心在一句话里："**摘要承担阅读和理解的作用，权威状态由对应的写入与变更规则维护。**"

注意这不是"把摘要做得更好"。这是**剥夺摘要的权威**：目标、待办、归属、阻塞条件、证据全部放在模型上下文之外，每轮注入的是状态内核的当轮读取，摘要只是辅助理解的读物。蒸馏丢了约束，伤的是可读性，不是行动依据。

他给的五条机制，我逐条对着他引用的 commit（`105c4bc15`）核验过源码，抽查三条：

- **交付连续性**。`delivery_continuity.ts`（394 行）真实存在，决策输入正是他声称的三要素：已有实质进展（previous delivery outcome）、仍可执行（actionable + capability_ready）、归属有效（claimed_by）。preemption 列表里 `heartbeat_receipt` 是一等公民——心跳到来时优先继续进行中的交付，而不是把局部工作拽回去重新过顶层判断。这一条直接回应"宏观目标压住局部工作"。
- **三层步幅**。stride RFC 确认三层嵌套：Effect stride（工具反馈边界）、Delivery stride（结算边界）、Authority stride（scope/acceptance/权限变更边界），并且写明"一次 scheduler tick 本身不能制造任何一种语义迁移"。顶层干预本来就不该每轮发生——压顶问题在这一层是被设计排除的，不是被缓解的。
- **replan 义务**。1511 行的 replan 契约里，义务跨 replan 存活，恢复须由同一 Agent 的规范终态重建原义务，一次成功结算不能被另一轮复用来跳过验证。"没有有效变化依据的复盘不能自动解除义务"是有代码兜底的，不是修辞。

这五点之外，我追问"每轮到底注入什么"时，他又指了两个更具体的入口。读完我认为，这两个才是"注入什么"问题的直接答案：

- **planning horizon（计划视界）**。`quota_planning_horizon_v0` 是一个有界、只读的上下文：让 agent 在当前选中的 todo 之外，看到它所在的战略链——事实来源、策略决策、准入、验证。协议文档自己写了动机："只显示那个门禁，会让模型去优化眼前这片叶子"；planning horizon 让这条有界的链可见，但"不悄悄替换掉选中的 todo"。最能说明问题的是一个默认值：把 goal 原文一并带进来的 `planning_horizon_goal` 选项**默认关闭**——LoopX 对"每轮注入什么"的默认答案是，连目标原文都不注入，只给当前工作周围一圈有界视界。
- **replan context**。启用 `evidence_conditioned_v1`（同样默认关闭）后，若历史中存在已被接受、绑定证据的 vision 路线，replan 上下文会返回上次路线决定连同其后的进度证据，因果顺序取自追加位置而非时间戳，"又做一次复盘或只引用一次"不会消耗证据。这和 succession advisory 一脉相承：把"上次决定了什么、之后实际做了什么"重建成可读模型交回判断，而不是自动失效。文档全程保持着苛刻的诚实边界——"这些是记录中的观测，不等于执行或收益的证明"。

他回答的最后一段同样值得引用："状态格式正确、传递成功，不代表语义一定完整……任意自然语言约束在超长运行中始终不丢失，仍是需要持续验证的目标。"作者自己把边界画出来了。

## 四、分野的精确定义

两种药方摆在一起，最容易说错的一句话是"一个外置状态一个不外置"——不对，TinyKG 图数据库本身就是外置状态，两家的状态都在模型之外。

真正的分野在一个更窄的点上：**每轮注入上下文的东西，是派生物还是权威本身。**

metacodes 注入的是派生物——DAG 路径摘要是对图状态的蒸馏计算，模型拿到的行动依据是二手的，路线成败押在蒸馏保真上。LoopX 注入的是权威状态的当轮读取，不经过蒸馏层。分野在最具体的那个机制上看得最清楚：两家都在解决"让当前工作看到自己在路径上的位置"——metacodes 给的是蒸馏出来的路径摘要，LoopX 给的是 planning horizon，一份权威行的有界只读投影，而且默认连目标原文都不带。

由此两家的失效模式也不同：metacodes 的坑是蒸馏丢了约束而没有检测器；LoopX 的坑是**状态 schema 表达不了的约束无处安放**——能被外置状态看守的，只有能被结构化的那部分约束。作者承认的那句"任意自然语言约束不丢失仍未验证"，承认的就是这半边。

所以两种药方的坑是同一个无人区的两种形态：**没法被结构化的约束，怎么证明它还在。** 这一格，论文没有，产品没有，两位作者各自承认了一半。

也别把分野读成对立。两条路线不互斥：DAG 节点完全可以持有权威、摘要只做视图——那是兼有两家之长的形态。现在下任何胜负结论都太早，一边还没开工，一边的验收文化不允许它提前宣布胜利。

## 五、一枚硬币的两面

读 LoopX 源码时有一个发现，单看两条路线都看不到：**连续性保护会放大渐进型漂移。**

交付连续性让局部工作不被顶层目标拽回——这是治千轮之病的药。但同一枚硬币的另一面是：局部一直"对"，方向慢慢偏，不触发任何单点告警。保护局部连续性的机制越强，渐进漂移的通道越宽。

LoopX 自己知道这一点。仓库里躺着一份 `goal-direction-baseline` RFC（目标方向基线），状态是"已接受、Partial"，M1 候选明确写着"不代表通用运行时启用"。**药已落地，解药还是候选**——这个时差不是疏漏，是长程系统当前的真实边界：我们先把"敢深入"做出来了，"不跑偏"还在图纸上。

跑稳是一组机制，跑好是另一组机制，而这枚硬币提醒还有第三组：记得为什么跑。

## 六、RSI 的地基，铺了一半

最后说一篇和这个病同源的文章。LoopX 作者最近发了《通用长程是 RSI 的先决条件》，主张递归自我改进的瓶颈不在"AI 能不能改自己的代码"，而在改进能否累积——目标延续、反馈累积、改进接续。

审计之前先复核。他文末附了统计复核命令，我跑了一遍：快照 8,613 总提交、6,848 非合并、三期凌晨数、最近 14 天 1,356 个、单日最高 144——**全部精确成立**。（一个方法坑值得记录：`%cI` 保留提交写入时的原始时区偏移，直接取小时会算错，必须先换算到北京时间；全库约 209 个提交带着 +04:00/+07:00/+10:00 的偏移，这本身倒是"社区贡献交织"的旁证。）

他点名挂出的三个证物我也逐个看了：对 RSI-Harness 的采用审计（102 行，四档决策表，唯一采用项附实测：33MB 文件记账峰值内存 68MB→47KB）、落地它的 PR #4984（含 157 行边角回归）、以及外部贡献者修正其 JSONL 分帧 bug 的 PR #5119。"采用→验证→被社区修正"的链条是真实的。

但把文章的主张和代码对表，落差在同一个地方：RSI 文说"改进接续"已经在发生，代码里对应的 Reward Memory（约 30 个模块，反馈证据、策略内容与动作 authority 三分，设计严谨）是**默认关闭的实验能力**，五个宿主有三个的自动写回标注为未接入。叙事用的是完成时，机制用的是进行时。

同一个时态差还有第二处：他指路让我去看的两个机制——planning horizon 的 goal 携带与 replan context——恰好也都是默认关闭的实验开关，文档自己写明"送达和隔离测试不能证明模型采用及收益"。指路指到实验区，这不是揭短：一个把实验默认关闭、把收益标为未证的项目，指路往实验区指，恰恰是诚实。

所以这篇文章的论点，我读完源码之后反而更信了——但方向和它自己说的不一样：通用长程确实是 RSI 的先决条件，只是从代码看，**连"目标延续"这块地基，铺得最好的项目也只铺了一半**。vision_checkpoint 管路线修订，succession  advisory 把对账摆到人面前，direction baseline 还是 RFC。地基在施工，这不妨碍它是对的——但谈递归之前，得先承认我们还在打地基。

## 七、负面清单更新两格

上一篇的负面清单这轮可以更新两格：

- **replan 对账**加注：LoopX 给出的现实答案是两件套：successor 链接 `lineage_only`，检测到接续问题强制 `authoring_decision_required`；replan context 再把"上次决定与后续证据"重建成只读模型交回判断。不自动失效、不自动转移，对账决策显式摆回人面前。自动对账语义依然无人区，但"拒绝自动化"成了一种被实现、而且带证据回读的立场。
- **新增一格：不可结构化约束的存续。** 蒸馏保真检测（metacodes 的坑）与 schema 外约束看护（LoopX 的坑）是同一格的两种形态。两种药方谁能先填上这一格，取决于各自承诺的那个评估——一边承诺了"做完之后严格评估"，一边把"每条规则的反面写成变异测试"当日常。

这是这个行业少有的好消息：两种药方都押上了可检验的承诺。药效如何，评估出来就知道——这一次，赌注是公开的。
